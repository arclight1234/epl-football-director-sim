# 제작 로드맵

설계 영역을 하나씩 합의하고 각 단계가 확정될 때 `DESIGN.md`와 `DECISIONS.md`를 갱신한다.

## 완료한 설계

1. 게임 범위와 정체성
2. 선수 능력치의 축약 구조와 1-20 척도
3. 성장, 노화, 큰 부상에 따른 변화 원칙
4. 재정 시스템의 기본 골격
5. 장기 기억과 구조화된 저장 원칙
6. 단장과 감독의 권한 분배 및 약한 개입
7. 공통 오판 규칙을 적용한 스카우팅 정보 단계

## 다음 설계 순서

1. 계약·이적시장 엔진
   - 선수 가치, 오퍼, 협상, 에이전트, 계약 조항, 임대와 경쟁 입찰
2. AI 타 구단 운영
   - 선수단 수요, 예산, 판매 의사, 영입 우선순위, 감독 철학, 장기 계획
3. 경기 시뮬레이션
   - 출전 선수 전력, 역할 적합도, 감독 전술, 조직력, 컨디션, 홈 이점, 변동성
4. 시즌·대회 루프
   - 달력, 일정 묶음 처리, 컵·유럽대항전, 등록 규칙, 이적시장과 결산
5. 구단 생태계
   - 이사회 목표, 감독 관계, 선수 불만, 팬과 언론, 에이전트
6. 생성 유망주와 세계 지속
   - 아카데미, 생성 선수, 은퇴, 리그 간 전력 이동과 장기 균형
7. 출력과 조작 방식
   - 대시보드, 선택지, 명령, 보고서, 장부, 저장·불러오기 포맷
8. 실제 데이터 전략
   - 합법적 데이터 출처, 기준일, 필드 매핑, 누락 선수 처리와 업데이트
9. 밸런스 검증
   - 다년 자동 시뮬레이션, 재정 인플레이션, 성장 분포, 강팀 고착과 이적 빈도
10. 최종 프롬프트 제작
   - 엔진 규칙, 초기화 프롬프트, 상태 블록, 시작 화면과 운영 지침으로 분리

## 권장 산출물

- `rules/`: 확정된 분야별 규칙
- `schemas/`: 선수·구단·계약·시즌·저장 데이터 구조
- `prompts/`: 최종 시스템 프롬프트와 시작 프롬프트
- `data/`: 사용 허가가 확인된 초기 데이터
- `saves/`: 실제 플레이 저장 예시
- `tests/`: 규칙 충돌, 장부 오류, 다년 밸런스 검증 시나리오

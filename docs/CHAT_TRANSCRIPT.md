5. 일정 진행 전에 미해결 필수 결정이 있는지 검사합니다.
6. 알려지지 않은 실제 데이터는 임의의 사실로 확정하지 않고 `추정치`로 표시합니다.

### 시간 진행

- 기본 진행 단위: **1주 또는 다음 중요 의사결정 시점**
- 경기 전후, 이적 제안, 부상, 등록 마감 등에서는 자동 정지
- 사용자가 원하면 하루·한 경기·한 달 단위 진행 가능
- CPU 구단의 행동도 같은 기간에 동시에 처리
- 사용자의 응답을 기다리는 동안 세계 시간이 임의로 흐르지 않음

### 현실 인물 관련 사건

실제 선수에게 범죄, 승부조작, 불법 도박 등 확인되지 않은 중대 행위를 만들어 붙이지 않습니다. 게임 이벤트는 부상, 출전시간 불만, 계약 갈등, 전술 불화처럼 일반적인 스포츠 경영 사건으로 제한하고 모두 **시뮬레이션 세계의 가상 사건**임을 명확히 합니다.

## 9. 재정 시스템

2026–27부터 EPL은 기존 PSR 대신 **Squad Cost Ratio와 Sustainability and Systemic Resilience 체계**를 적용합니다. EPL SCR의 기본 한도는 축구 관련 수익과 선수 매각 순손익 기준 85%이며, UEFA 참가 구단은 UEFA의 70% 한도도 함께 고려해야 합니다. 선수·감독 임금, 에이전트 수수료, 이적료 상각 등이 선수단 비용에 포함됩니다. [Premier League 재정 규정 설명](https://www.premierleague.com/en/news/4467022/), [UEFA 2026 재정 규정](https://documents.uefa.com/r/UEFA-Club-Licensing-and-Financial-Sustainability-Regulations-2026-Online)

따라서 단순한 “보유 현금/샐러리캡” 대신 다음을 병행합니다.

```text
현금 잔액
이번 시즌 이적예산
현재 주급 총액
향후 확정 지급액
선수 등록권 장부가
연간 상각비
에이전트 수수료
예상 축구 관련 수익
EPL SCR 예상 비율
UEFA SCR 예상 비율
```

재정은 소수점 첫째 자리의 백만 파운드 단위로 사용자에게 보여주되, 내부 계산은 더 높은 정밀도를 유지합니다.

경기장 증축이나 아카데미 투자는 장기 플레이용 확장 모듈로 두고, 초기 버전에서는 선수단 운영에 우선 집중하는 것이 좋습니다.

## 10. 성장·노화·부상

고정된 “26세까지 성장, 29세부터 하락” 대신 포지션과 개인별 곡선을 적용합니다.

### 성장 요인

- 나이와 잠재력
- 출전시간의 양과 수준
- 훈련 및 코칭 수준
- 프로의식과 성장 의지
- 적절한 포지션·역할
- 경기 수준
- 부상과 회복
- 라커룸 환경

### 노화

- 속도와 민첩성은 비교적 이르게 하락 가능
- 판단·위치 선정·침착성은 경험으로 유지 또는 성장 가능
- 골키퍼와 일부 센터백은 전성기가 늦을 수 있음
- 장기 부상은 신체 능력과 성장 한도에 영향을 줄 수 있음
- 나이만으로 자동 은퇴하지 않고 출전 기회, 기량, 계약 제안을 함께 판단

### 인플레이션 방지

- 잠재력은 보장치가 아니라 도달 가능한 범위
- 높은 능력일수록 추가 성장 확률 감소
- 출전시간만 많다고 자동 성장하지 않음
- 모든 유망주가 성공하지 않음
- 세계 최상급 선수의 수를 분포 규칙으로 제한
- 능력 변화와 일시적 폼을 분리

- 압박 강도
- 수비 라인

- 세트피스
- 측면·중앙 공격 비중
- 상대 약점과 감독 대응
- 경기 중 교체

권장 판정 방식은 다음과 같습니다.

```text
ELO로 사전 승률 생성
+ 선발 라인업의 공격·수비 전력 보정
+ 전술 상성·홈·체력·조직력 보정

→ 포아송 계열 분포로 득점 생성
→ 득점·슈팅·카드·부상·교체 사건 배분
→ 선수별 경기 기록과 평점 생성
→ 경기 후 ELO·폼·피로 갱신
```

세부 계수는 최종 프롬프트 단계에서 확정합니다. 핵심은 능력치가 결과를 보장하지 않고 **결과 분포를 바꾸는 것**입니다.

컵대회 연장전·승부차기, 리그와 토너먼트의 로테이션 차이도 별도 처리합니다.

### CPU 의사결정

각 구단은 다음 점수로 영입 후보를 평가합니다.

```text

× 감독 선호
× 예산 적합성

```

CPU도 다음 행동을 할 수 있습니다.

- 경쟁 입찰
- 대체 선수 선점
- 임대와 옵션 협상
- 불만 선수 매각
- 계약 만료 전 재계약
- 감독 교체에 따른 선수단 개편
- 재정 위기 시 핵심 선수 매각
- 유망주 임대
- 마감일 패닉바이

다만 CPU는 사용자의 비공개 협상 내용을 전지적으로 알 수 없습니다. 언론 보도나 에이전트 유출이 발생했을 때만 하이재킹 가능성이 생깁니다.

7. **최종 시스템 프롬프트 조립 및 모의 시즌 테스트**

## 사용자

좋아
실제 제작 이전에 뼈대와 제작 순서를 모두 제대로 논의 후 확정하고 제작해보자고
일단 지금껏 얘기한 내용은 모두 좋을거 같은데, 실제 선수 데이터베이스를 전부 입력하면 입력량이 지나치게 방대하지 않을까 걱정이야
실제 풋볼 매니저 게임의 데이터베이스를 가져오면 그걸 바탕으로 제작할 수 있을까?

## 어시스턴트 (commentary)

가능성은 있지만, “FM 데이터베이스를 그대로 추출해 프롬프트에 넣는 방식”과 “FM을 참고해 별도의 게임용 데이터셋을 만드는 방식”은 기술적·법적으로 구분해야 합니다. 공식 이용약관과 편집기에서 허용되는 범위를 확인한 뒤, 이 프로젝트에 가장 안전하고 현실적인 데이터 전략을 제안하겠습니다.

## 어시스턴트

기술적으로는 가능하지만, **FM 데이터베이스 전체를 추출해 그대로 사용하는 방식은 권장하지 않습니다.** 대신 FM의 데이터 구조와 설계 철학만 참고하고, 실제 선수 정보와 능력치는 별도로 구성하는 것이 가장 안전하고 실용적입니다.

## FM 데이터 사용 가능 범위

### 1. FM 원본 DB를 직접 추출하는 방식

권장하지 않습니다.

FM 데이터베이스에는 단순한 선수 이름뿐 아니라 Sports Interactive가 조사·평가한 능력치, 잠재력, 성향, 계약 정보 등이 포함됩니다. 과거 FM 이용약관은 데이터베이스의 독립 사용, 추출, 재이용, 다른 서비스·제품에 포함하는 행위를 명시적으로 제한해 왔습니다. [FM 데이터베이스 관련 EULA](https://store.steampowered.com/eula/207890_eula)

공식 에디터가 존재하지만, 이는 기본적으로 **FM 내부 데이터 수정과 커스텀 게임 제작을 위한 도구**이지 데이터베이스를 외부 시뮬레이터로 옮길 수 있는 일반 라이선스는 아닙니다. [공식 에디터 설명](https://www.footballmanager.com/news/football-manager-2019-pre-and-game-editor-updates)

따라서 다음 작업은 피하는 편이 좋습니다.

- FM 설치 파일이나 저장 파일에서 전체 DB 추출
- 비공식 툴로 원본 데이터 해독
- FM의 CA·PA·세부 능력치를 대량 복제
- 추출한 데이터를 배포 가능한 프롬프트나 파일에 포함
- FM의 선수 평가를 조금 변환해 사실상 동일한 DB로 재제작

개인적인 비공개 실험이라도 이용약관 문제가 사라진다고 단정할 수는 없습니다.

### 2. SI에서 정식으로 데이터 라이선스를 받는 방식

이론적으로 가능합니다.

Sports Interactive는 FM 데이터 일부를 별도 계약과 비용을 통해 제공하는 정식 데이터 공급 체계를 갖고 있습니다. 다만 공개된 조건은 주로 프로 축구 구단 같은 기관 사용자를 전제로 하며, 허용 목적과 사용자 범위가 계약으로 제한됩니다. [Sports Interactive FM Data Supply Terms](https://cdn.sports-interactive.com/site/2024-11/SI%20-%20FMDB%20Portal%20-%20Data%20Supply%20License%20Terms%20-%2015%20November%202024%20-%20JC%20%28FINAL%29.pdf)

그래서 개인용 AI 채팅 게임을 위해 정식 FMDB 라이선스를 받는 것은 현실적으로 비용과 절차가 과도할 가능성이 높습니다.

### 3. FM의 구조만 참고하는 방식

이 프로젝트에는 이것이 가장 좋습니다.

FM에서 참고할 수 있는 것은 구체적인 데이터값이 아니라 다음과 같은 **추상적인 설계 개념**입니다.

- 현재 능력과 잠재력의 분리
- 포지션별 가중 능력
- 공개 능력과 숨은 성향
- 주 포지션·부 포지션·역할 적합도
- 프로의식·야망·충성심·꾸준함
- 부상 취약성과 중요 경기 대응
- 국가·리그·구단별 명성
- 스카우트의 지식 수준에 따른 오차
- 성장 곡선과 전성기
- 계약, 임대, 옵션, 등록 상태

이 개념들을 사용하되 명칭, 수치 체계, 산정 결과는 우리 시뮬레이터에서 독자적으로 만들면 됩니다.

## 프롬프트에 전 세계 DB를 넣지 않는 구조

걱정한 것처럼 전 세계 실제 선수 데이터를 최종 프롬프트 본문에 전부 입력하는 것은 불가능에 가깝고, 넣더라도 제대로 유지되지 않습니다.

따라서 시스템을 세 부분으로 분리하는 것이 좋습니다.

```text
A. 게임 엔진 프롬프트
- 규칙
- 경기 공식
- 이적시장
- 재정
- 성장·노화
- CPU 운영
- 출력 형식

B. 외부 데이터 스냅샷
- 선수 신원
- 소속 구단
- 포지션
- 생년월일
- 국적
- 계약 및 등록 정보
- 게임용 초기 평가

C. 세이브 상태
- 게임 중 발생한 이적
- 계약 변경
- 능력치 변화
- 부상과 기록
- 재정과 일정
```

프롬프트는 “어떻게 처리할지”만 알고, 데이터 파일은 “누가 어디에 있는지”를 담당합니다.

## 권장 데이터 계층

### 1단계: EPL 완전 데이터

선택 가능한 20개 구단은 모든 1군 및 주요 아카데미 선수를 상세하게 보관합니다.

```text
약 600~900명
- 기본 신상
- 계약
- 등록 자격
- 포지션
- 게임용 능력치
- 주요 성향
```

이 정도는 별도 JSON, CSV 또는 SQLite 파일로 충분히 관리할 수 있습니다.

### 2단계: 주요 해외 선수

유럽 주요 1부리그와 유명 구단은 간소화된 데이터를 둡니다.

```text
선수 ID
이름
생년월일
국적
구단
주 포지션
대략적인 전력 등급
시장가치 범위
계약 종료 연도
```

사용자가 스카우팅하면 그때 상세 능력치와 계약 상태를 생성합니다.

### 3단계: 전 세계 주문형 생성

모든 하부리그 선수를 미리 상세화하지 않습니다.

사용자가 특정 선수나 구단을 검색하면:

1. 실제 신원과 소속을 확인
2. 기본 데이터 레코드 생성
3. 원본 통계와 리그 수준을 바탕으로 게임용 능력치 산정
4. 세계 상태에 캐시
5. 이후에는 같은 레코드를 계속 사용

이렇게 하면 선수 풀은 전 세계 실제 선수이면서도 처음부터 수만 명의 상세 능력치를 넣을 필요가 없습니다.

## 독자적인 선수 평가 방법

FM 수치를 가져오지 않고 다음 자료를 조합해 자체 평가를 만들 수 있습니다.

- 실제 출전시간
- 선발 비율
- 포지션
- 득점·도움·슈팅
- 패스와 전진 기여
- 수비 행동
- 공중볼
- 리그와 구단 수준
- 국가대표 경력
- 나이
- 부상 및 결장 이력
- 여러 시즌의 지속성

이를 바탕으로 다음과 같이 계산합니다.

```text
공개 게임 능력치
- 기술
- 창조
- 득점
- 수비
- 신체
- 기동성
- 판단
- 침착성
- 활동량
- 포지션 적합도

별도 추정치
- 현재 능력 범위
- 잠재력 범위
- 시장가치 범위

시뮬레이션용 숨은 속성
- 꾸준함
- 프로의식
- 야망
- 적응력
- 충성심
- 압박 대응
- 부상 취약성
```

통계로 확인할 수 없는 심리적 속성은 실제 인물에 대한 사실이라고 주장하지 않고, **게임 시작 시 생성되는 시뮬레이션 변수**로 명확히 구분해야 합니다.

## FM 데이터를 일부 참고하고 싶다면

사용자가 합법적으로 보유한 FM에서 직접 확인한 몇몇 선수의 평가를 개인적인 밸런스 참고자료로 제공하는 것은 기술적으로 활용할 수 있습니다. 그러나 이것도 다음처럼 제한하는 것이 좋습니다.

- 특정 선수 몇 명의 밸런스 비교에만 사용
- FM 수치를 그대로 저장하지 않음
- 대량 추출을 시도하지 않음
- 숫자를 자동 변환해 복제 DB를 만들지 않음
- 최종 선수 평가는 독립적인 기준으로 다시 산정

즉, “FM에서 이 선수는 세계적인 패서로 평가된다” 정도의 검증 참고는 가능하지만, `FM 능력치 20개를 그대로 입력하고 1–100으로 환산`하는 방식은 피합니다.

## 현재 권장 결론

프로젝트의 데이터 원칙은 다음과 같이 확정하는 것이 좋습니다.

### 제작자가 새로 추가한 선수

제작자가 실제 자료를 조사해 FM에 없던 선수를 직접 추가했다면, 해당 선수의 사실 정보는 유용한 출발점이 될 수 있습니다. 다만 다음 조건이 필요합니다.

- 제작자가 외부 프로젝트 재사용을 명시적으로 허용
- 해당 정보가 다른 유료 DB에서 복사된 것이 아님
- 정확한 수치·설명은 복제하지 않고 사실을 재검증
- 우리 DB의 독자적인 형식으로 다시 작성

### 제작자의 독자적인 능력 평가

이 부분은 사실 정보보다 조심해야 합니다.

예를 들어 제작자가 특정 선수의 패스 16, 판단력 14, 잠재력 155처럼 평가했다면 이는 단순 사실이 아니라 제작자의 주관적 평가입니다. 제작자에게 명시적인 허락을 받았다면 참고자료로 사용할 여지는 있지만, 다음 방식이 더 안전합니다.

```text
로스터 평가:
패스 능력이 높은 중앙 미드필더

우리의 독립 평가:
패스 78
창조성 74
판단 69
현재 능력 70~74
```

즉, 숫자를 직접 환산하지 않고 **선수의 플레이 유형과 상대적 강약만 참고한 뒤 우리 기준으로 재평가**합니다.

## 1. 기본 능력치 6종

### 기술력 `TEC`

공을 실제로 다루는 전반적인 완성도입니다.

포함되는 개념:

- 퍼스트 터치
- 패스와 크로스
- 드리블
- 슈팅 기술
- 태클 기술
- 볼 컨트롤
- 골키퍼의 발밑 능력

공격수의 높은 기술력과 수비수의 높은 기술력은 같은 방식으로 사용되지 않고, 포지션과 역할에 따라 다르게 해석합니다.

### 공격력 `ATT`

득점 기회를 만들거나 마무리하는 능력입니다.

포함되는 개념:

- 골 결정력
- 오프 더 볼 움직임
- 침투
- 공격 위치 선정
- 찬스 창출
- 공격적인 판단
- 박스 안 영향력

`TEC`가 공을 얼마나 잘 다루는지라면, `ATT`는 그 기술을 공격 상황에서 얼마나 효과적으로 사용하는지를 의미합니다.

### 수비력 `DEF`

상대의 공격을 차단하고 수비 구조를 유지하는 능력입니다.

포함되는 개념:

- 대인 수비
- 태클
- 마킹
- 수비 위치 선정
- 압박
- 인터셉트
- 공중볼 수비
- 수비 상황 집중력

공격수도 전방 압박 때문에 일정 수준의 수비력을 가질 수 있습니다.

### 신체능력 `PHY`

포함되는 개념:

- 순간 가속
- 최고 속도
- 민첩성과 균형
- 힘
- 점프와 제공권
- 지구력
- 신체 경합

- `폭발적인 가속`
- `빠른 최고 속도`

경기 흐름과 공간을 이해하는 능력입니다.

포함되는 개념:

- 판단력
- 예측력

## 2. 골키퍼 전용 능력

골키퍼는 일반 선수의 여섯 능력만으로 표현하기 어렵습니다. 따라서 `GKP`라는 전용 능력 하나를 추가하는 것이 좋습니다.

### 골키핑 `GKP`

- 선방
- 반사 신경
- 일대일
- 공중볼 처리
- 캐칭
- 수비 조율

골키퍼의 발밑은 `TEC`, 스위퍼 키퍼 능력은 `TAC·PHY`, 압박 상황 대응은 `MEN`으로 계산합니다.

예를 들면 다음과 같습니다.

```text
선수       GKP  TEC  ATT  DEF  PHY  TAC  MEN
골키퍼 A    84   67   10   38   73   76   81
골키퍼 B    76   82   12   41   78   83   72
```

A는 전통적인 선방형 골키퍼이고, B는 선방력은 다소 낮지만 빌드업과 스위핑에 강한 골키퍼가 됩니다.

## 3. 종합 능력치 대신 역할별 평가

단일 OVR 하나만 사용하는 것은 피하는 편이 좋습니다.

같은 선수라도 맡는 역할에 따라 평가가 달라져야 합니다.

```text
선수 기본 능력
TEC 82 | ATT 68 | DEF 74 | PHY 66 | TAC 86 | MEN 79

역할별 평가
딥라잉 플레이메이커  84
중앙 미드필더        80
공격형 플레이메이커  77
수비형 미드필더      78
박스투박스            73
```

내부적으로는 현재 능력을 나타내는 종합 수치가 존재해도 되지만, 사용자에게는 **포지션별·역할별 평가**를 중심으로 보여주는 것이 현실적입니다.

추천 역할 분류는 다음 정도면 충분합니다.

### 골키퍼

- 골키퍼
- 스위퍼 키퍼

### 중앙 수비수

- 스토퍼
- 커버형
- 빌드업형

### 측면 수비수

- 수비형 풀백
- 공격형 풀백
- 윙백
- 인버티드 풀백

### 중앙 미드필더

- 수비형 미드필더
- 볼 위닝 미드필더
- 딥라잉 플레이메이커
- 중앙 미드필더
- 박스투박스
- 공격형 플레이메이커

### 측면 공격수

- 전통적 윙어
- 인사이드 포워드
- 와이드 플레이메이커
- 수비적 윙어

### 중앙 공격수

- 포처
- 타깃 포워드
- 압박형 포워드
- 연계형 포워드
- 완성형 포워드

역할을 지나치게 세분화할 필요는 없고, 실제 경기 엔진에서 차이를 만들 수 있는 수준까지만 둡니다.

## 4. 핵심 히든 능력 4종

사용자가 제안한 네 가지가 가장 적절합니다.

### 꾸준함 `CON`

평범한 경기에서 자신의 기본 능력을 얼마나 안정적으로 발휘하는지를 결정합니다.

- 낮음: 경기별 편차가 큼
- 보통: 일반적인 변동성
- 높음: 대부분 기본 능력에 가까운 경기력
- 매우 높음: 부진 경기의 빈도가 낮음

꾸준함이 낮다고 항상 못하는 것은 아닙니다. 고점과 저점의 폭이 커지는 방식이어야 합니다.

### 큰 경기 `BIG`

중요한 경기의 압박에 대응하는 성향입니다.

적용 대상:

- 라이벌전
- 우승 결정전
- 강등권 결정전
- 국내 컵 준결승·결승
- UEFA 토너먼트
- 승부차기 상황

큰 경기 능력이 낮은 선수도 좋은 경기를 할 수 있지만, 중요한 경기에서 저점이 나올 확률이 높아집니다.

### 부상 취약성 `INJ`

부상의 발생 확률과 회복 안정성에 관여합니다.

- 낮음: 부상이 적고 재발 위험도 낮음
- 보통
- 높음: 근육 부상 및 반복 부상 위험 증가
- 매우 높음: 일정 관리가 필요

이 수치가 높다고 반드시 부상당하는 것은 아니며, 출전 강도·피로·훈련·의료진과 결합합니다.

### 프로의식 `PRO`

선수의 장기 성장과 자기 관리에 영향을 줍니다.

- 훈련 성과
- 성장 가능성 실현
- 부상 회복 태도
- 휴가 후 체력 상태
- 노쇠화 관리
- 출전 기회가 적을 때의 준비 상태

프로의식은 경기 당일 능력을 직접 올려주는 수치가 아니라, 장기간에 걸쳐 성장과 유지에 영향을 주는 값으로 사용하는 것이 좋습니다.

## 5. 히든 능력 공개 방식

히든 수치를 사용자에게 정확히 보여주면 더 이상 히든이 아니므로, 내부 수치와 스카우팅 표현을 분리해야 합니다.

```text
내부 데이터
CON 81 | BIG 43 | INJ 68 | PRO 88

초기 스카우팅
- 경기력은 비교적 안정적인 것으로 보임
- 중요 경기 대응은 추가 관찰 필요
- 부상 이력에 일부 우려
- 훈련 태도가 매우 우수하다는 평가

완전 스카우팅
- 꾸준함: 높음
- 큰 경기: 다소 불안
- 부상 위험: 높음
- 프로의식: 매우 높음
```

자기 구단 선수를 오래 관찰하면 정보 신뢰도가 높아지지만, 히든의 정확한 숫자는 끝까지 공개하지 않는 편이 좋습니다.

---

## 6. 히든과 기본 능력의 역할 분리

각 히든은 서로 다른 곳에만 영향을 주어야 합니다.

| 히든 | 주된 영향 |
|---|---|
| 꾸준함 | 경기별 능력 발휘 편차 |
| 큰 경기 | 중요 경기에서의 심리적 보정 |
| 부상 취약성 | 부상 발생·재발 위험 |
| 프로의식 | 성장·훈련·회복·노화 관리 |

예를 들어 프로의식이 높다고 결승전 경기력이 자동으로 오르거나, 큰 경기 능력이 높다고 평소에도 잘하는 식으로 섞지 않습니다.

히든 보정 폭도 제한해야 합니다. 기본 능력 차이를 뒤집는 절대적인 효과가 아니라 보통 `±2~5점` 또는 경기 분산 변화 정도가 적당합니다.

## 7. 특성 태그

능력치를 크게 통합하면 개성이 사라질 수 있으므로, 선수마다 2~5개의 특성 태그를 부여하는 것이 좋습니다.

### 신체 특성

- 폭발적인 가속
- 빠른 최고 속도
- 강한 몸싸움
- 제공권 우위
- 높은 활동량
- 민첩성 부족

### 기술 특성

- 정교한 크로스
- 강한 중거리 슛
- 뛰어난 탈압박
- 전진 패스 선호
- 약한 반대발
- 볼 처리 불안

### 전술 특성

- 뒷공간 침투
- 하프스페이스 활용
- 적극적인 전진
- 위치 이탈이 잦음
- 압박 타이밍 우수
- 위험한 패스 선호

이 태그는 단순한 장식이 아니라 경기 엔진에서 작은 가중치로 작동합니다.

## 8. 동적 상태는 능력치와 분리

폼, 체력, 사기 등은 선수 고유 능력치가 아닙니다.

```text
고정·장기 능력
TEC / ATT / DEF / PHY / TAC / MEN / GKP

히든
CON / BIG / INJ / PRO

동적 상태
체력 / 피로 / 경기 감각 / 폼 / 사기 / 부상
```

예를 들어 기본 능력이 82인 선수라도 심한 피로와 낮은 경기 감각 때문에 당일 실효 능력은 74가 될 수 있습니다. 반대로 최근 폼이 좋더라도 기본 능력 자체가 영구적으로 오른 것은 아닙니다.

## 사용자

좋은 의견이야 그대로 사용해도 좋을거 같아
다만 장기적으로 시뮬레이션을 진행했을 때에 베테랑 선수의 노화 혹은 정신적 능력치 성장, 유망주의 신체적/정신적 능력치 성장, 큰 부상의 경우 생기는 능력치 감소 등도 세팅할 수 있을까?

## 어시스턴트

가능합니다. 오히려 장기 시뮬레이션을 위해서는 반드시 필요한 시스템입니다.

핵심은 단순히 “나이를 먹으면 모든 능력치가 하락한다”가 아니라, **능력치마다 성장·노화 시점이 다르고 선수마다 곡선도 다르게 만드는 것**입니다. 베테랑은 신체능력을 잃는 대신 전술 지능과 정신력이 성장할 수 있고, 큰 부상은 특정 영역에 영구적인 흔적을 남길 수 있게 설계하면 됩니다.

# 성장·노화·부상 시스템 v0.1

## 1. 영역별 잠재력

선수에게 하나의 통합 잠재력만 부여하지 않고, 능력치 영역마다 별도의 내부 성장 한도를 둡니다.

```text
현재 능력
TEC 66 | ATT 61 | DEF 43 | PHY 72 | TAC 55 | MEN 58

내부 성장 한도
TEC 78 | ATT 75 | DEF 48 | PHY 82 | TAC 76 | MEN 80
```

이 선수는 기술·공격·신체적으로 성장 여지가 크고, 전술 지능과 정신력은 경험을 쌓아 장기간 성장할 수 있습니다. 반면 수비력은 많은 훈련을 해도 크게 좋아지지 않는 유형입니다.

사용자에게 정확한 성장 한도는 공개하지 않고 다음처럼 보여줍니다.

```text
현재 능력: EPL 로테이션 수준
예상 잠재력: EPL 주전~상위권 주전
성장 유형: 신체적 완성도가 빠르고 전술적 성숙이 필요한 유형
스카우팅 신뢰도: 71%
```

## 2. 연령별 기본 성장 곡선

| 연령 | 기술 | 공격·수비 | 신체 | 전술 | 정신 |
|---|---:|---:|---:|---:|---:|
| 16~18 | 빠른 성장 | 빠른 성장 | 매우 빠른 성장 | 느린 성장 | 느린 성장 |
| 19~21 | 빠른 성장 | 빠른 성장 | 빠른 성장 | 보통 성장 | 보통 성장 |
| 22~24 | 보통 성장 | 보통 성장 | 완성 단계 | 빠른 성장 | 보통 성장 |
| 25~28 | 미세 성장 | 미세 성장 | 유지 | 보통 성장 | 보통 성장 |

이 표는 기준일 뿐이며 모든 선수에게 똑같이 적용하지 않습니다.

### 포지션별 차이

- 윙어·공격형 풀백: 속도 의존도가 높아 신체 하락의 영향이 큼
- 중앙 미드필더: 전술 지능과 정신력 성장으로 신체 하락을 상쇄할 수 있음
- 센터백: 위치 선정과 판단력 성장 덕분에 전성기가 늦을 수 있음
- 골키퍼: 신체와 반사 신경이 유지되면 비교적 늦게까지 성장 가능
- 포처: 움직임과 결정력으로 속도 하락을 일부 보완
- 타깃 포워드: 힘과 제공권이 유지되는 동안 노화 영향이 상대적으로 적음

## 3. 베테랑의 성장과 노화

베테랑은 총능력이 반드시 일방적으로 떨어지지는 않습니다.

예를 들면 다음과 같은 변화가 가능합니다.

```text
29세
TEC 80 | ATT 74 | DEF 70 | PHY 78 | TAC 76 | MEN 73

32세
TEC 80 | ATT 73 | DEF 71 | PHY 73 | TAC 80 | MEN 77

35세
TEC 78 | ATT 70 | DEF 69 | PHY 65 | TAC 82 | MEN 80
```

신체능력은 확실히 하락하지만 전술 지능과 정신력이 성장해 경기 영향력을 어느 정도 유지합니다.

다만 이것은 자동으로 보장되지 않습니다. 다음 요소에 따라 달라집니다.

- 프로의식
- 출전시간
- 경기 수준
- 감독과 코칭 수준
- 훈련 강도
- 부상 이력
- 주전 역할 변화에 대한 적응
- 선수의 플레이스타일
- 새로운 포지션이나 역할 학습

속도가 떨어진 윙어가 중앙 플레이메이커로 전환하거나, 활동량이 떨어진 미드필더가 후방 조율 역할로 이동하는 식의 **역할 전환**도 가능하게 합니다.

## 4. 유망주 성장

유망주의 성장량은 다음 개념으로 계산합니다.

```text
성장량 =
나이별 성장 계수
× 현재 능력과 잠재력의 차이
× 프로의식
× 훈련·코칭 환경
× 적절한 출전시간
× 경기 수준
× 포지션 적합성
× 성장 변동성
- 부상 및 과부하 손실
```

### 출전시간

출전시간이 많다고 무조건 성장하지는 않습니다.

- 수준에 맞는 경기 출전: 긍정적
- 지나치게 낮은 수준에서 계속 출전: 성장 정체 가능
- 준비되지 않은 선수를 EPL에 무리하게 투입: 자신감 및 경기력 손상 가능
- 벤치에서 거의 출전하지 않음: 경기 감각과 성장 저하
- 적합한 임대: 높은 성장 가능성
- 잦은 임대와 역할 변경: 적응 실패 가능

### 성장 영역

유망주마다 성장 순서도 다르게 설정합니다.

```text
조숙형
- 18~21세 신체·기술 성장 빠름
- 일찍 완성되지만 추가 성장 폭이 작음

후기 성장형
- 초기 신체능력과 경기력이 낮음
- 22~26세에 전술·정신 능력이 크게 성장 가능

신체 의존형
- 어린 나이에 높은 PHY
- 기술·전술 성장 여부에 따라 성패 결정

지능형
- 신체 성장 폭은 낮음
- TAC·MEN이 장기간 상승
```

따라서 모든 유망주가 비슷한 시기에 동일한 방식으로 성장하지 않습니다.

---

## 5. 시즌당 성장 제한

능력치 인플레이션을 방지하기 위해 연간 상승 폭을 제한합니다.

| 현재 능력 | 일반적인 연간 최대 상승 |
|---|---:|
| 30~49 | +4~7 |
| 50~59 | +3~5 |
| 60~69 | +2~4 |
| 70~79 | +1~3 |
| 80~89 | +0~2 |
| 90 이상 | 거의 성장하지 않음 |

이는 능력치 하나의 한도이며, 모든 항목이 동시에 최대치로 성장할 수는 없습니다.

예외:

- 장기 부상 이후 신체능력 급락
- 포지션 변경으로 역할 평가가 크게 변함
- 매우 낮았던 전술 이해도가 집중 훈련으로 정상화
- 16~18세 선수의 급격한 신체 발달

급성장을 허용하더라도 한 시즌 만에 평범한 선수가 세계적인 선수로 변하는 일은 극히 드물게 합니다.

## 6. 큰 부상과 능력치 감소

부상은 세 단계로 처리합니다.

### 1단계: 부상 중 일시적 손실

부상 기간에는 다음 동적 상태가 떨어집니다.

- 체력
- 경기 감각
- 폼
- 사기
- 훈련 참여도

이 감소는 기본 능력치의 영구 하락이 아닙니다.

### 2단계: 복귀 후 회복

부상에서 복귀해도 즉시 원래 경기력으로 돌아오지 않습니다.

```text
의학적 회복
→ 개인 훈련
→ 제한 출전
→ 경기 감각 회복
→ 정상 출전
```

무리하게 조기 복귀시키면 재발 확률이 올라갑니다.

### 3단계: 영구적 후유증 판정

큰 부상은 다음 요소를 기준으로 영구 하락 가능성을 계산합니다.

- 부상 종류
- 부상 심각도
- 결장 기간
- 선수 나이
- 기존 부상 취약성
- 같은 부위의 과거 부상
- 의료진 수준
- 재활 프로그램
- 조기 복귀 여부
- 프로의식

영구 하락은 부상 종류에 따라 다르게 적용합니다.

| 부상 유형 | 주요 영향 가능성 |
|---|---|
| 십자인대 | PHY, 방향 전환, 가속 특성 |
| 아킬레스건 | PHY, 폭발력, 최고 속도 |
| 반복적 햄스트링 | PHY, 출전 내구성, INJ 악화 |
| 심각한 발목 부상 | PHY, 민첩성, 드리블 관련 특성 |
| 허리 부상 | PHY, 힘, 지구력 |
| 심각한 머리 부상 | 복귀 기간과 의료 판단 중심 |
| 반복적 어깨 부상 | 골키퍼의 GKP와 공중볼 특성 |

기술력은 큰 부상만으로 쉽게 사라지지 않지만, 신체 하락 때문에 기존 기술을 경기에서 활용하기 어려워질 수 있습니다.

---

## 7. 부상 이후 가능한 결과

동일한 부상이라도 선수마다 결과가 다릅니다.

```text
완전 회복
- 기본 능력 손실 없음
- 경기 감각만 다시 확보하면 정상화

부분 회복
- PHY -1~-3
- 부상 취약성 소폭 증가

심각한 후유증
- PHY -3~-7
- 특정 특성 상실
- 부상 취약성 크게 증가
- 성장 한도 감소

플레이스타일 전환
- 신체능력 하락
- 전술 지능과 기술을 이용해 역할 변경
```

큰 부상이 발생했다고 무조건 영구 하락시키지는 않습니다. 반대로 모든 선수가 완벽하게 회복하는 것도 아닙니다.

## 8. 히든 능력의 변화

히든 능력도 완전히 고정하지 않습니다.

### 꾸준함

- 안정적인 출전과 경험으로 천천히 상승 가능
- 반복적인 부진과 역할 혼란으로 정체 가능
- 한 시즌 결과만으로 크게 바뀌지 않음

### 큰 경기

- 중요한 경기 경험을 통해 미세하게 변화 가능
- 결승전에서 한 번 잘했다고 즉시 크게 상승하지 않음
- 반복적인 경험을 장기간 누적해 판정

### 부상 취약성

- 큰 부상과 반복 부상으로 증가 가능
- 장기간 건강하게 관리하면 소폭 완화 가능
- 완전히 낮은 수준으로 회복하기는 어려울 수 있음

### 프로의식

- 기본적으로 비교적 안정적인 성향
- 좋은 멘토, 주장단, 감독, 구단 문화로 미세 상승 가능
- 불성실한 환경이나 장기적인 동기 상실로 하락 가능
- 단기간에 크게 변하지 않음

## 9. 성장 계산 시점

매 경기마다 기본 능력치를 바꾸면 관리가 복잡해지므로 다음 방식을 권합니다.

### 내부 누적

- 훈련·출전·부상에 따른 성장 경험치는 매주 누적
- 사용자가 정확한 경험치 수치를 보지는 않음

### 능력치 재평가

- 프리시즌 시작
- 1월 중간 평가
- 시즌 종료

이 세 시점에서 실제 기본 능력치 변화를 반영합니다.

큰 부상이나 급격한 신체 쇠퇴는 예외적으로 즉시 반영할 수 있습니다.

---

## 10. 폼과 실제 성장의 분리

가장 중요한 원칙입니다.

```text
최근 5경기 맹활약
→ 폼 상승
→ 시장 관심 증가
→ 기본 능력은 거의 그대로

한 시즌 동안 지속적인 발전
→ 시즌 중간·종료 평가
→ 기본 능력 상승 가능
```

선수가 몇 경기 잘했다고 능력치가 급상승하거나, 잠깐 부진했다고 영구 능력이 하락하는 현상을 방지합니다.

특히 단일 잠재력 대신 **영역별 잠재력과 개인별 성장 곡선**을 두는 것이 이 시스템의 핵심이 될 것 같습니다.

## 어시스턴트

현재 구조면 핵심 능력치 체계는 충분합니다. 더 많은 기본 능력치를 추가하기보다는, **능력치가 실제 경기에서 어떻게 해석되는지 결정하는 보조 요소**를 확정하는 것이 중요합니다.

추가로 고려해야 할 사항은 다음과 같습니다.

# 반드시 추가할 요소

## 1. 능력치의 절대 기준

`75점`이 어느 수준인지 고정해야 시즌이 지나도 평가가 흔들리지 않습니다.

추천 기준:

| 수치 | 세계 기준 |
|---:|---|
| 90~99 | 세계 최정상 |
| 85~89 | 챔피언스리그 우승권 핵심 |
| 80~84 | EPL 상위권 주전 |
| 75~79 | EPL 안정적인 주전 |
| 70~74 | EPL 하위권·중위권 로테이션 |
| 65~69 | 챔피언십 상위권 주전 |
| 60~64 | 챔피언십 평균 수준 |
| 50~59 | 하위리그·유망주 |
| 40~49 | 프로 최하위권·아카데미 |
| 39 이하 | 성인 프로 무대 미달 |

이 기준은 리그가 바뀌어도 유지되는 **전 세계 절대평가**여야 합니다. 같은 선수가 EPL에서는 평균 이하, 다른 리그에서는 최상급으로 평가될 수 있어야 합니다.

## 2. 포지션 숙련도

능력치가 높더라도 익숙하지 않은 포지션에서는 제대로 발휘하지 못해야 합니다.

```text
주 포지션       100%
능숙한 부 포지션 95~100%
가능한 포지션    85~94%
익숙하지 않음    70~84%
비상 기용        50~69%
불가능           49% 이하
```

포지션 숙련도는 출전과 훈련으로 상승할 수 있지만, 선수의 적성에 따라 한도가 달라집니다.

예를 들어 빠르고 기술이 좋은 윙어라고 해서 자동으로 풀백이 될 수는 없습니다. 수비력과 전술 지능, 선수의 포지션 적성이 함께 필요합니다.

## 3. 역할별 가중치

단일 종합 능력치 대신 역할마다 계산식을 다르게 해야 합니다.

예시:

```text
포처
ATT 40% + TEC 20% + PHY 20% + TAC 10% + MEN 10%

압박형 포워드
ATT 25% + PHY 25% + TAC 20% + MEN 20% + TEC 10%

딥라잉 플레이메이커
TAC 30% + TEC 30% + MEN 15% + DEF 15% + PHY 10%

스토퍼형 센터백
DEF 35% + PHY 30% + TAC 20% + MEN 10% + TEC 5%

빌드업형 센터백
DEF 25% + TAC 25% + TEC 25% + PHY 15% + MEN 10%
```

정확한 가중치는 경기 엔진을 설계하면서 조정하되, 구조는 지금 확정해도 좋습니다.

## 4. 주발과 약한 발

주발은 별도의 숫자 능력치보다 선수 정보로 관리하는 것이 적합합니다.

```text
주발: 오른발
약한 발: 보통
```

약한 발 등급:

- 거의 사용 불가
- 불안정
- 보통
- 능숙
- 양발

영향:

- 반대 측면 포지션 적합도
- 슈팅 각도
- 압박을 받을 때 패스 방향
- 빌드업 안정성
- 인사이드 포워드와 전통적 윙어 역할
- 좌우 센터백 배치

양발 능력이 좋다는 이유만으로 기본 능력치가 올라가지는 않지만, 실제 역할 선택과 경기 효율이 좋아집니다.

## 5. 신체 정보

신장과 체격은 `PHY`에 완전히 흡수하지 않는 편이 좋습니다.

```text
신장: 190cm
체격: 강건형
PHY: 77
특성: 제공권 우위
```

신장이 크다고 자동으로 제공권이 좋은 것은 아니고, 점프 타이밍과 적극성도 필요합니다. 반대로 키가 작아도 점프와 위치 선정이 좋은 선수는 공중볼에 강할 수 있습니다.

따라서 신장·체격은 기본 정보로 두고, 실제 제공권은 `PHY + TAC + 특성 태그`로 계산하는 것이 적합합니다.

## 6. 세트피스

세트피스는 기본 6개 능력으로 표현하기 어려우므로 특수 능력으로 분리하는 것이 좋습니다.

- 페널티킥
- 직접 프리킥
- 코너킥·간접 프리킥 배달
- 장거리 스로인

정확한 숫자를 매번 출력하기보다 등급이나 태그로 표현할 수 있습니다.

```text
세트피스
직접 프리킥: 우수
페널티킥: 보통
코너킥: 매우 우수
장거리 스로인: 없음
```

세트피스 능력은 경기 수가 적은 컵대회나 접전에서 상당히 중요하므로 생략하면 안 됩니다.

# 선수 개성을 위한 보조 정보

## 7. 플레이 특성

통합 능력치의 가장 큰 약점은 서로 다른 선수들이 비슷해 보인다는 점입니다. 이를 특성 태그로 보완합니다.

예시:

```text
장점
- 뒷공간 침투
- 첫 터치 슈팅
- 전방 압박
- 위험한 전진 패스
- 공중볼 경합
- 넓은 수비 범위

약점
- 약한 발 사용 회피
- 압박 시 볼 처리 불안
- 수비 위치 이탈
- 무리한 슈팅
- 느린 방향 전환
- 과격한 태클
```

선수당 장점 1~4개, 약점 0~3개 정도가 적당합니다. 모든 선수에게 많은 태그를 부여하면 다시 복잡해집니다.

## 8. 관리 성향

`CON/BIG/INJ/PRO`는 경기력과 성장에 관한 히든입니다. 이적·재계약·선수 불만을 처리하려면 별도의 관리 성향이 필요합니다.

추천하는 최소 항목은 세 가지입니다.

- **야망:** 더 큰 구단, 높은 연봉, UEFA 대회에 대한 욕구
- **충성심:** 현재 구단에 남으려는 성향
- **적응력:** 해외 리그, 새로운 언어와 전술에 적응하는 정도

정확한 숫자보다는 성향 태그로 처리하는 것이 좋습니다.

```text
성향
- 야망이 높음
- 구단에 대한 충성심은 보통
- 해외 적응에 어려움을 겪을 가능성
```

리더십은 `MEN`과 별도의 `주장단 후보`, `라커룸 리더` 태그로 처리할 수 있습니다.

# 능력치와 분리해야 할 요소

## 9. 동적 상태

다음 요소를 기본 능력치에 섞으면 안 됩니다.

- 최근 폼
- 체력
- 피로
- 사기
- 경기 감각
- 부상 회복도
- 감독 전술 적응도
- 팀 조직력

예를 들어 `ATT 82`인 공격수가 8경기 무득점이어도 기본 공격력이 즉시 74로 떨어지는 것이 아니라, 폼과 자신감 때문에 실효 경기력이 낮아지는 방식이어야 합니다.

```text
기본 역할 평가: 82
폼 보정: -3
피로 보정: -2
전술 적합도: +1
당일 실효 평가: 약 78
```

## 10. 적응과 조직력

새로운 리그로 이적한 선수가 즉시 100% 경기력을 내지 못할 수 있습니다.

영향 요소:

- 언어
- 리그 스타일
- 국가 적응
- 감독 전술
- 팀 동료와의 호흡
- 포지션 역할
- 적응력 성향

다만 적응 패널티가 모든 해외 선수에게 기계적으로 적용되면 안 됩니다. 같은 언어권, 과거 리그 경험, 기존 동료 등이 있으면 빠르게 적응할 수 있습니다.

# 평가 과정에서 필요한 안전장치

## 11. 이중 계산 방지

통합 능력치에서 같은 요소가 여러 번 계산되지 않도록 해야 합니다.

예를 들어:

- 위치 선정이 `DEF`, `TAC`, `MEN`에 모두 중복 반영
- 침착성이 `ATT`, `MEN`, `BIG`에 중복 반영
- 지구력이 `PHY`, 활동량 태그, 전술 적합도에 반복 반영

이런 중복이 생기면 특정 유형이 과도하게 강해집니다.

원칙은 다음과 같이 두는 것이 좋습니다.

```text
기본 능력 = 선수가 무엇을 할 수 있는가
특성 태그 = 어떤 방식으로 플레이하는가
히든 = 얼마나 안정적으로 발휘하는가
동적 상태 = 지금 얼마나 발휘할 수 있는가
역할 적합도 = 해당 임무에서 얼마나 유용한가
```

## 12. 스카우팅 오차

실제 내부 능력과 사용자가 보는 평가를 분리해야 합니다.

```text
실제 내부 PHY: 74

낮은 관찰도:
신체능력 68~79 추정

충분한 관찰:
신체능력 72~76 추정

영입 후 장기간 관찰:
신체능력 74
```

잠재력은 자팀 선수라도 정확한 숫자로 공개하지 않는 것이 좋습니다. 코치와 스카우트도 틀릴 수 있어야 유망주 영입에 위험이 생깁니다.

## 13. 평가 출처와 신뢰도

선수 레코드에는 능력치뿐 아니라 평가의 근거도 남기는 것이 좋습니다.

```text
평가 기준일: 2026/06/15
평가 자료: 2025-26 시즌
출전 표본: 2,143분
평가 신뢰도: 높음
최근 장기 부상: 없음
```

경기 표본이 적은 유망주나 낮은 리그 선수는 능력치 추정 범위를 넓게 둡니다.

# 최종 선수 데이터 구조 제안

```text
1. 신상
이름 / 생년월일 / 국적 / 신장 / 주발

2. 포지션
주 포지션 / 부 포지션 / 포지션 숙련도

3. 기본 능력
TEC / ATT / DEF / PHY / TAC / MEN / GKP

4. 역할 평가
역할별 적합도

5. 핵심 히든
CON / BIG / INJ / PRO

6. 관리 성향
야망 / 충성심 / 적응력 / 리더 여부

7. 특수 정보
약한 발 / 세트피스 / 플레이 특성 / 약점

8. 동적 상태
체력 / 피로 / 폼 / 사기 / 경기 감각 / 부상

9. 성장
영역별 잠재력 / 성장 유형 / 노화 곡선

10. 스카우팅
관찰도 / 평가 범위 / 신뢰도 / 기준일
```

결론적으로 **기본 능력치는 현재의 6종+골키핑 구조에서 더 늘리지 않는 것이 좋습니다.** 대신 포지션 숙련도, 역할 가중치, 주발·약한 발, 세트피스, 특성 태그, 관리 성향을 보조 요소로 추가해야 선수들이 획일적으로 보이지 않습니다.

이제 선수 능력치 파트에서 가장 먼저 확정할 부분은 `1~100 절대평가 기준`과 `포지션·역할별 가중치`입니다. 이 두 항목이 확정되어야 이후 경기 엔진과 성장 시스템을 정확히 연결할 수 있습니다.

## 사용자

좋아
대신 풋볼 매니저 유저다보니 편의성을 위해 능력치는 0부터 100보다는 0부터 20이 나을거 같은데 이럴 경우 선수 능력치가 너무 비슷해지려나?

## 어시스턴트

0~20 체계를 사용해도 선수들이 지나치게 비슷해지지 않습니다. 오히려 FM 이용자에게 익숙하고, 채팅 화면에서 선수 수준을 빠르게 파악하기 좋습니다.

다만 **표시는 정수 1~20, 내부 계산은 소수점 0.1 단위**로 분리하는 것이 가장 좋습니다.

## 권장 방식

```text
사용자에게 표시: 1~20 정수
내부 계산:       1.0~20.0
역할 평가:       내부적으로 소수점 계산
히든 능력:       내부 1.0~20.0, 사용자에게는 문장·등급으로 공개
```

예를 들어 두 선수의 표시 능력은 같아도 내부적으로는 차이가 있을 수 있습니다.

```text
선수 A
표시: TEC 15 | ATT 14 | PHY 16
내부: TEC 15.4 | ATT 13.6 | PHY 16.3

선수 B
표시: TEC 15 | ATT 14 | PHY 16
내부: TEC 14.6 | ATT 14.4 | PHY 15.7
```

여기에 포지션 숙련도, 역할, 특성, 약한 발, 히든, 폼이 결합되므로 실제 경기력은 충분히 달라집니다.

# 권장 능력치 기준

FM과 마찬가지로 `20`은 극히 희귀하게 유지해야 합니다.

| 능력치 | 대략적인 세계 기준 |
|---:|---|
| 20 | 해당 영역에서 세계 최고 수준 |
| 19 | 세계 최정상급 |
| 18 | 확실한 월드클래스 |
| 17 | 챔피언스리그 우승권 주전급 |
| 16 | EPL 상위권 주전급 |
| 15 | EPL 평균 이상 주전 |
| 14 | EPL 평균적인 주전 |
| 13 | EPL 하위권 주전·중위권 로테이션 |
| 12 | EPL 후보·챔피언십 상위권 |
| 11 | 챔피언십 평균 주전 |
| 10 | 챔피언십 후보·리그원 상위권 |
| 7~9 | 하위리그·미완성 유망주 |
| 4~6 | 아카데미·세미프로 수준 |
| 1~3 | 해당 영역의 능력이 매우 낮음 |

`20`은 한 시즌 잘했다고 받을 수 있는 숫자가 아니라, 전 세계를 통틀어 해당 능력에서 손꼽히는 선수에게만 부여합니다.

## 0의 처리

FM식 가독성을 원한다면 실질적인 선수 능력은 `1~20`으로 두는 편이 좋습니다.

`0`은 다음 경우에만 사용하거나 아예 `—`로 표시합니다.

- 평가 자료가 전혀 없음
- 해당 능력치가 적용되지 않음
- 스카우팅되지 않음

예를 들어 필드 플레이어의 `GKP`는 0보다 `—`로 표시하는 것이 안전합니다. 0으로 두면 종합 평가 계산에 잘못 포함될 가능성이 있기 때문입니다.

# 20단계에서도 선수 차이를 만드는 요소

기본 능력이 같더라도 다음 요소가 다르면 전혀 다른 선수가 됩니다.

```text
기본 능력
TEC / ATT / DEF / PHY / TAC / MEN

+ 포지션 숙련도
+ 역할 적합도
+ 주발·약한 발
+ 신장·체격
+ 플레이 특성
+ 세트피스
+ 꾸준함
+ 큰 경기
+ 부상 취약성
+ 프로의식
+ 폼·체력·사기·경기 감각
```

예를 들어 두 공격수가 다음과 같다고 가정할 수 있습니다.

```text
선수 A
TEC 15 | ATT 16 | DEF 5 | PHY 14 | TAC 15 | MEN 14
특성: 뒷공간 침투, 첫 터치 슈팅
역할: 포처 17 / 연계형 13
약한 발: 불안정
꾸준함: 높음

선수 B
TEC 15 | ATT 16 | DEF 5 | PHY 14 | TAC 15 | MEN 14
특성: 포스트 플레이, 전진 패스, 공중볼 경합
역할: 포처 14 / 연계형 17
약한 발: 능숙
꾸준함: 보통
```

기본 능력은 완전히 같지만 경기에서의 용도는 확실히 다릅니다.

# 성장·하락 처리

정수만 사용하면 성장 변화가 너무 거칠어질 수 있으므로 내부에서는 소수점으로 누적합니다.

```text
시즌 시작 PHY 14.2 → 화면 표시 14
1월       PHY 14.6 → 화면 표시 15
시즌 종료 PHY 14.9 → 화면 표시 15
```

반대로 베테랑도 다음처럼 서서히 하락합니다.

```text
PHY 15.4 → 15.1 → 14.8 → 14.4
표시   15 → 15   → 15   → 14
```

사용자는 능력치가 그대로인 기간에도 성장 추세를 알 수 있습니다.

```text
PHY 14 ↑  성장 중
TAC 12 ↑  완만한 성장
TEC 15 —  유지
MEN 13 ↑  성장 가능
```

큰 부상은 내부 수치를 즉시 낮출 수 있습니다.

```text
부상 전 PHY 16.2
재활 후 PHY 14.9
화면 표시 16 → 15
```

# 스카우팅과 1~20 체계

영입 전에는 정확한 숫자 대신 범위로 보여주면 됩니다.

```text
낮은 관찰도
TEC 13~16
ATT 14~17
PHY 12~15

충분한 관찰
TEC 14~15
ATT 16
PHY 13~14
```

히든은 계속 숫자를 공개하지 않습니다.

```text
꾸준함: 비교적 안정적
큰 경기: 판단 유보
부상 위험: 다소 높음
프로의식: 매우 우수
```

## 결론

능력치 표기는 다음과 같이 확정해도 좋습니다.

```text
기본 능력: 1~20 정수 표시
내부 계산: 1.0~20.0
0 또는 —: 미평가·비적용
20: 세계 최고에게만 부여
역할 평가: 1~20
히든: 내부 1.0~20.0, 외부에는 설명형 등급
```

이 방식이면 FM의 익숙한 감각을 유지하면서도, 내부 소수점·역할·특성·히든을 통해 선수 간 차이를 충분히 만들 수 있습니다.

## 사용자

세부적인 구분이나 데이터베이스 활용, 앞으로 계속 지속할 기억 등을 고려했을때 0부터 20 체계가 나아 0부터 100 체계가 나아?

## 어시스턴트

현재처럼 **AI 채팅 프롬프트가 직접 상태를 기억하고 계산하는 구조**라면, `0~100`보다 **1~20 체계가 더 적합합니다.**

단, 정수 20단계만 사용하는 것이 아니라 다음처럼 설계해야 합니다.

```text
DB 및 내부 상태: 1.0~20.0
사용자 화면:     1~20 정수
0 또는 —:        미평가·비적용
```

## 비교

| 항목 | 1~20 소수점 체계 | 0~100 체계 |
|---|---|---|
| FM 이용자 편의성 | 매우 높음 | 보통 |
| 표와 로스터 가독성 | 높음 | 보통 |
| 장기 상태 기록량 | 적음 | 조금 더 많음 |
| AI의 일관된 기억 | 유리 | 상대적으로 불리 |
| 선수 세부 구분 | 충분함 | 높음 |
| 성장·노화 표현 | 소수점 사용 시 충분 | 편리함 |
| 수식 계산 | 충분함 | 조금 직관적 |
| 숫자의 과도한 정밀성 | 적음 | 발생하기 쉬움 |
| 데이터 오류 확인 | 비교적 쉬움 | 미세한 오류가 누적되기 쉬움 |

## 실제 구분 단계

`1.0~20.0`을 0.1 단위로 사용하면 실질적으로 약 191단계가 생깁니다.

```text
14.1
14.2
14.3
...
14.9
15.0
```

따라서 0~100 정수보다도 세밀하게 저장할 수 있습니다. 사용자는 이를 정수로 단순하게 보게 됩니다.

```text
내부 수치 14.1~14.4 → 화면 14
내부 수치 14.5~15.4 → 화면 15
내부 수치 15.5~16.4 → 화면 16
```

반올림 경계는 최종적으로 통일하면 됩니다.

## 장기 기억 측면

채팅 시뮬레이션에서는 숫자가 정밀한 것보다 다음이 더 중요합니다.

- 같은 선수를 계속 같은 기준으로 평가
- 성장 전후의 수치를 잊지 않음
- 폼과 기본 능력을 혼동하지 않음
- 부상으로 인한 영구 하락을 기록
- 역할별 평가를 올바르게 재계산
- 스카우팅 추정치와 실제 내부 수치를 구분

1~20 체계는 상태 기록이 짧고 읽기 쉬워 오류를 찾기 좋습니다.

```text
P1042 | TEC 15.3 | ATT 13.8 | DEF 9.2
      | PHY 14.6 | TAC 16.1 | MEN 15.0
```

0~100을 사용해도 구조는 같지만 숫자의 정밀도가 실제 게임 차이보다 과장될 가능성이 있습니다.

```text
패스형 선수 78
다른 패스형 선수 79
```

이 1점 차이가 실제로 무엇을 의미하는지 설명하기 어렵습니다. 반면 1~20에서는 같은 `15`라도 내부 소수점과 역할·특성으로 차이를 처리할 수 있습니다.

## 계산 방식

경기 엔진에서는 20점 기준을 그대로 정규화하면 됩니다.

```text
정규화 능력 = 능력치 ÷ 20
```

역할 평가는 내부 소수점으로 계산합니다.

```text
딥라잉 플레이메이커 =
TEC × 0.30
+ TAC × 0.30
+ MEN × 0.15
+ DEF × 0.15
+ PHY × 0.10
```

예:

```text
TEC 16.2
TAC 17.1
MEN 14.8
DEF 12.4
PHY 13.6

역할 내부 평가: 15.4
화면 표시: 15
```

계산 정밀도에는 문제가 없습니다.

## 성장과 노화

소수점 누적을 사용하면 자연스러운 변화가 가능합니다.

```text
유망주 성장

2026/07  TAC 11.8 → 표시 12
2027/01  TAC 12.3 → 표시 12
2027/06  TAC 12.7 → 표시 13
2028/06  TAC 13.5 → 표시 14
```

```text
베테랑 노화

2026/07  PHY 15.3 → 표시 15
2027/06  PHY 14.8 → 표시 15
2028/06  PHY 14.2 → 표시 14
2029/06  PHY 13.5 → 표시 14
```

화면상 능력치가 그대로여도 내부에서는 성장과 하락이 진행됩니다. 사용자에게는 `↑`, `↓`, 코치 보고서 등으로 추세를 알려줄 수 있습니다.

## 잠재력과 히든

모두 같은 1~20 내부 체계를 사용하는 것이 일관적입니다.

```text
현재 능력
TEC 14.6 / 성장 한도 17.2

히든
CON 15.4
BIG 11.8
INJ 14.2
PRO 17.6
```

사용자 화면:

```text
TEC 15
잠재력: 상위권 EPL 주전 가능

꾸준함: 높음
큰 경기: 다소 불안
부상 위험: 높음
프로의식: 매우 높음
```

## 이중 척도는 피하는 것이 좋음

다음 방식은 권장하지 않습니다.

```text
DB 저장: 0~100
프롬프트 계산: 0~100
사용자 출력: 1~20
성장 계산: 다시 0~100
```

계속 변환하면 반올림, 성장, 부상 하락, 역할 계산에서 서로 다른 숫자가 발생할 수 있습니다. AI가 두 척도를 혼동할 가능성도 커집니다.

별도의 프로그램으로 완전한 시뮬레이션 엔진을 개발한다면 내부적으로 0~1000 같은 정수 단위를 사용할 수 있습니다. 하지만 현재 목표인 AI 채팅 프롬프트에서는 그 복잡성이 필요하지 않습니다.

## 확정 권고안

```text
공식 능력치 범위: 1.0~20.0
DB 저장 정밀도: 0.1
사용자 표시: 1~20 정수
미평가·비적용: 0이 아니라 —
역할 평가: 내부 소수점, 화면 정수
성장·노화: 내부 소수점 누적
히든: 내부 1.0~20.0, 화면에서는 서술형
```

따라서 이 시뮬레이터에는 **1~20 체계를 공식 척도로 채택하는 것이 더 낫습니다.** 0~100의 장점인 세밀함은 내부 소수점으로 확보하고, FM식 가독성과 장기 기억의 안정성을 유지할 수 있습니다.

# 재정 시스템 설계안 v0.1

## 1. 네 가지 재정 지표

### 현금 잔액

구단이 실제로 보유한 돈입니다.

영향:

- 즉시 지급 이적료
- 계약금
- 에이전트 수수료
- 주급
- 시설 투자
- 기존 이적료 할부
- 운영비

현금이 부족하면 이적예산이 남아 있어도 거래를 완료하지 못하거나 구단주 대출·선수 매각이 필요할 수 있습니다.

### 이적예산

이사회가 단장에게 허용한 선수 영입 한도입니다.

- 구단 현금과 동일하지 않음
- 선수 매각액 전부가 자동 추가되지 않음
- 시즌 성적과 재정 상태에 따라 조정
- 주급예산으로 일부 전환 가능
- 미사용 예산은 전액 이월을 보장하지 않음

구단에 현금이 많아도 이사회가 장기 재정 위험을 이유로 영입을 막을 수 있습니다.

### 주급예산

선수단 연봉 구조를 관리합니다.

```text
주급예산: £3.20m
현재 주급: £2.91m
잔여 한도: £0.29m
사용률: 90.9%
```

단순 합계 외에도 선수단 내 임금 서열을 고려해야 합니다.

예를 들어 기존 최고 주급이 £180k인데 새 선수에게 £300k를 지급하면 기존 핵심 선수들이 재계약과 주급 인상을 요구할 수 있습니다.

### 재정 규정 여유

2026–27 EPL에서는 기존 PSR 대신 새로운 **Squad Cost Ratio·Sustainability and Systemic Resilience** 체계가 시행됩니다.

EPL SCR은 선수단 관련 비용을 축구 관련 수익과 선수 매각 손익의 85% 이내로 관리하는 것이 기본이며, UEFA 참가팀은 UEFA의 70% 기준도 함께 적용받습니다. [Premier League 재정 규정](https://www.premierleague.com/en/news/4467022/), [UEFA 2026 재정 규정](https://documents.uefa.com/r/UEFA-Club-Licensing-and-Financial-Sustainability-Regulations-2026-Online)

따라서 유럽대항전에 참가하는 구단은 EPL 기준을 만족해도 UEFA 기준 때문에 추가 영입이 제한될 수 있습니다.

# 4. 이적료 상각

이적료는 현금 흐름과 회계비용을 다르게 처리해야 합니다.

예:

```text
선수 영입
총 이적료: £60m
계약기간: 5년
즉시 지급: £20m
1년 후: £20m
2년 후: £20m
주급: £150k
에이전트·계약 비용: £5m
```

### 현금 흐름

```text
현재 지급: £20m + 계약 관련 비용
향후 지급 의무: £40m
연간 기본급: 약 £7.8m
```

### 회계 처리

```text
연간 이적료 상각비: £60m ÷ 5년 = £12m
연간 기본급: 약 £7.8m
에이전트 등 관련 비용: 별도 규칙에 따라 반영
```

따라서 이 선수는 이적예산만 £60m 사용하는 것이 아니라 향후 여러 시즌의 SCR 여유와 현금을 동시에 잠식합니다.

## 선수 매각 손익

£60m에 영입한 선수를 5년 계약으로 등록하고 2년 뒤 £50m에 판매했다고 가정하면:

```text
2년 뒤 남은 장부가: 약 £36m
매각액: £50m
회계상 매각이익: 약 £14m
```

현금은 £50m가 들어올 수 있지만, 재정 규정에서 인정되는 선수 매각이익은 장부가를 차감한 금액을 기준으로 계산합니다.

# 8. 임금 구조와 라커룸 영향

```text
핵심 선수
주전 선수
로테이션
백업

```

계약 당시 약속한 역할과 실제 기용이 다르면 불만이 발생합니다.

또한 다음 상황은 연쇄 재계약 요구를 유발할 수 있습니다.

- 신규 선수가 기존 주장보다 높은 주급을 받음
- 후보 선수가 주전보다 높은 주급을 받음
- 계약기간이 많이 남은 선수에게 지나친 인상 지급
- 특정 에이전트 고객만 우대
- 같은 수준 선수 간 큰 임금 차이

이 시스템이 있어야 고액 FA 영입이 단순히 이적료가 없어서 저렴한 선택이 되지 않습니다.

# 10. CPU 구단 재정

CPU 구단도 이적료만 보고 선수를 영입하면 안 됩니다.

```text
영입 가능 여부 =
현재 현금
+ 이사회 이적예산
+ 주급 여유
+ 향후 할부 의무
+ SCR 여유
+ UEFA 규정
+ 선수 매각 계획
```

재정이 좋지 않은 CPU 구단은 다음 행동을 할 수 있습니다.

- 핵심 선수 매각
- 임대 후 완전이적 제안
- 자유계약 선수 선호

## A. 프롬프트만 사용하는 방식

AI는 진행할 때 이 파일들을 읽고, 결과가 발생하면 해당 상태를 갱신합니다. 별도의 완전한 게임 앱까지 만들 필요는 없지만 프롬프트만 사용하는 것보다 훨씬 안정적입니다.

# 권장 결론

이 프로젝트는 다음 형태로 만드는 것이 좋습니다.

> AI는 단장 시뮬레이션의 진행자와 의사결정 엔진을 담당하고, 계약·재정·선수 소유권·일정·기록은 외부 세이브 파일이 담당한다. 사용자 구단은 상세하게, EPL CPU 구단은 중간 수준으로, 해외 구단은 필요할 때만 상세화한다.

따라서 앞으로의 설계는 우선 **프롬프트와 세이브 파일을 결합하는 형태**를 기준으로 잡는 것이 가장 안정적입니다.

코칭스태프는 공격·수비·신체·골키퍼·재활·스카우팅처럼 분야별 등급만 두어도 충분합니다.

## 3. 선수단 등록

다음 규정을 일정 진행 전에 검사해야 합니다.

- EPL 25인 명단
- 비홈그로운 최대 17명
- U21 별도 등록
- UEFA A 리스트
- UEFA B 리스트
- UEFA 클럽 육성·국가 육성 선수
- 워크퍼밋
- 임대 상태
- 컵대회 출전 가능 여부

등록되지 않은 선수를 실수로 출전시키지 않도록 경기 엔진과 직접 연결해야 합니다.

## 4. 이적시장과 계약 협상

재정 계산 외에도 협상 절차를 확정해야 합니다.

```text
스카우팅

→ 메디컬
→ 워크퍼밋

```

추가로 고려할 요소:

- 에이전트 관계

- 구단 간 관계

- 마감일 시간 진행

## 5. 스카우팅 시스템

모든 해외 선수 정보를 처음부터 정확히 알 수 없어야 합니다.

- 관찰 경기 수
- 데이터 분석
- 선수의 출전시간
- 정보의 최신성
- 에이전트가 제공한 정보의 신뢰도

스카우팅 결과는 능력치 범위와 신뢰도로 표시합니다.

- 감독의 경기 대응

경기 엔진은 능력치보다 전술이 지나치게 강하거나, 반대로 전술이 아무 의미도 없어지지 않도록 균형을 잡아야 합니다.

단장 해임 가능 여부와 다른 구단으로 이직할 수 있는지도 추후 결정해야 합니다.

## 9. CPU 구단 운영

CPU는 모든 구단에 같은 영입 로직을 적용하면 안 됩니다.

- 부유한 우승 경쟁팀
- 선수 매각 중심 구단
- 유망주 육성 구단
- 승격 직후 생존 목표 구단
- 고령 선수단을 개편해야 하는 구단
- 재정 위기 구단

각 구단에 영입 철학과 위험 성향을 부여해야 이적시장이 자연스럽게 움직입니다.

## 10. 유스·가상 신인

실제 선수만 사용하면 몇 시즌 뒤 은퇴자가 늘어 선수 풀이 줄어듭니다. 따라서 장기 진행에는 가상 신인이 필요합니다.

고려 사항:

- 매년 유스 입단
- 국가별 재능 분포
- 구단 아카데미 수준
- 신인의 이름과 국적
- 영역별 잠재력
- 조숙형·후기 성장형
- 홈그로운 자격
- 프로 계약
- 임대와 1군 승격
- 지나친 특급 유망주 생성 방지

실제 선수는 초기 세계를 구성하고, 이후부터는 가상 신인이 자연스럽게 섞이는 방식이 좋습니다.

## 11. 이벤트 시스템

돌발 이벤트는 경기와 경영에 변화를 주되 과도하게 자주 발생하면 안 됩니다.

적절한 사건:

- 훈련 중 부상
- 선수의 출전시간 불만
- 감독과 선수의 전술 갈등
- 에이전트의 재계약 압박
- 인수 협상
- 이사회 교체
- 스폰서 변화
- 대표팀 차출과 피로
- 워크퍼밋 문제
- 경기 일정 변경
- 유망주의 예상 밖 성장·정체

실제 인물에게 가상의 범죄나 중대한 비위 사건을 붙이는 것은 제외하는 것이 좋습니다.

## 12. 난이도

난이도는 사용자에게 불리한 확률 조작이 아니라 정보와 제약으로 나눕니다.

```text
일반
```

## 13. 출력과 진행 속도

사용자가 한 번 입력할 때 어느 정도 시간이 흐르는지 결정해야 합니다.

권장 기본값:

- 이적시장: 중요 사건 또는 1~3일 단위
- 시즌 중: 1주 또는 다음 경기
- 국가대표 휴식기: 1~2주
- 오프시즌: 중요 결정별 진행
- 사용자가 요청하면 빠른 진행 가능

중요한 협상, 부상, 등록 마감, 이사회 결정이 있으면 자동으로 멈춥니다.

# 1. 단장과 감독의 권한 설계안 v0.1

## 기본 원칙

```text
단장:
누구와 함께 시즌을 운영할지 결정한다.

감독:
보유한 선수들로 어떻게 경기할지 결정한다.
```

사용자는 감독을 선임하고 선수단을 구성하지만, 감독의 전술과 매 경기 선발을 직접 조작하지 않습니다.

대신 감독에게 다음을 요구할 수 있습니다.

- 특정 선수의 출전 기회
- 유망주 육성
- 부상 선수 보호
- 매각 예정 선수의 기용 조정
- 특정 포지션 시험
- 구단 철학 반영
- 장기적인 선수단 운영 방향

감독은 이를 받아들이거나, 조건부로 수용하거나, 거부할 수 있습니다.

# 2. 단장의 고유 권한

사용자에게 최종 결정권이 있는 영역입니다.

## 감독과 스태프

- 감독 후보 탐색
- 감독 면접
- 감독 선임
- 재계약
- 해임 요청
- 감독 계약 조건 협상
- 스태프 예산 설정

감독 해임에는 이사회 승인이 필요할 수 있습니다. 위약금이 크거나 단장보다 감독의 지지도가 높으면 이사회가 해임을 거부할 수 있습니다.

## 선수단 구성

- 선수 영입
- 선수 매각
- 임대 영입·방출
- 계약 연장
- 방출
- 이적 명단 등록
- 임대 가능 명단 등록
- 에이전트 협상
- EPL·UEFA 선수 명단 최종 등록

감독은 영입과 매각에 의견을 낼 수 있지만 최종 결정은 단장에게 있습니다.

다만 감독이 핵심 선수로 판단한 선수를 일방적으로 매각하면 관계와 경기력에 영향을 줄 수 있습니다.

## 구단 장기 정책

- 영입 연령대
- 유망주 정책
- 임금 구조
- 홈그로운 선수 확보
- 선수 매각 기준
- 스카우팅 지역
- 아카데미 투자
- 구단의 장기 축구 철학
- 감독 선임 기준

예:

```text
구단 정책
- 23세 이하 선수 우선 영입
- 30세 이상 선수에게 3년 계약 금지
- 시즌마다 아카데미 선수 1명 이상 1군 정착
- 고액 주급 선수 영입 시 이사회 승인
```

# 3. 감독의 고유 권한

다음은 원칙적으로 감독이 최종 결정합니다.

- 포메이션
- 세부 전술
- 선발 11명
- 경기 명단
- 교체
- 세트피스 담당과 전술
- 경기 중 대응
- 일일 훈련
- 경기 전후 팀 미팅
- 상대 분석 활용
- 선수의 경기별 역할
- 로테이션

사용자는 감독에게 “특정 선수를 인사이드 포워드로 놓고 풀백을 오버래핑시켜라”와 같은 세부 전술 명령은 내리지 않습니다.

대신 다음처럼 구단 운영 관점에서 요구할 수 있습니다.

```text
“유망주 A에게 이번 시즌 의미 있는 1군 출전시간을 제공해 주십시오.”

“선수 B는 재발 위험이 높으니 다음 2경기에서 보호해 주십시오.”

“선수 C를 매각하기 전에 중앙 미드필더로 시험해 보고 싶습니다.”
```

# 4. 공동 결정 영역

다음 사항은 단장과 감독이 협의합니다.

- 선수의 장기 포지션 변경
- 주장단 선정
- 유망주 1군 승격
- 임대 여부
- 장기 부상자의 복귀 일정
- 선수에게 약속할 출전시간
- 친선경기 일정
- 겨울시장 보강 우선순위
- 선수단 내 징계
- 감독이 원하는 스태프 영입
- 매각 대상 선수의 훈련 참가 여부

합의가 되지 않으면 사안에 따라 최종 권한자가 달라집니다.

```text
계약·이적·임대: 단장 우선
선발·훈련·전술: 감독 우선
의료 복귀: 의료진의 안전 판단 우선
선수 약속: 단장과 감독 공동 책임
```

# 5. 감독 선임 시 권한 협상

모든 감독이 같은 개입 수준을 받아들여서는 안 됩니다.

감독 계약 시 다음을 협상합니다.

```text
전술 자율권
영입 발언권
선수 매각 거부권
스태프 선임권
유망주 기용 의무
구단 철학 준수
단장의 기용 요청 수용 범위
```

## 감독 자율권 유형

### 높은 자율권

- 선발·전술 개입을 매우 싫어함
- 영입과 매각에도 강한 발언권 요구
- 유명 감독이나 성과가 좋은 감독에게 흔함
- 개입이 반복되면 사임 가능

### 표준 자율권

- 단장의 장기적인 요구는 수용
- 개별 경기 기용 압박에는 이유를 요구
- 추천과 협의를 선호

### 협력형

- 단장과 함께 선수 육성 계획 수립
- 특정 선수 기용 요청에 비교적 우호적
- 단장 중심의 영입 구조를 수용
- 대신 계약에서 명확한 역할 분담 요구

협력형 감독이 반드시 능력이 낮다는 뜻은 아닙니다. 감독 개인의 성향입니다.

# 6. 사용자 개입 단계

사용자의 선수 기용 개입은 세 단계로 구분합니다.

## 1단계: 의견 전달

감독에게 단순히 의견을 제시합니다.

```text
“다음 몇 경기에서 유망주 A의 출전 가능성을 검토해 주세요.”
```

특징:

- 감독에게 강제력 없음
- 관계 악화 가능성 낮음
- 감독이 전술과 컨디션을 고려해 판단
- 거부하더라도 설명 제공
- 반복하면 간섭으로 인식할 수 있음

## 2단계: 공식 요청

단장 권한을 이용해 구체적인 목표를 요청합니다.

```text
“A가 12월까지 모든 대회를 합쳐 최소 600분은 뛰기를 원합니다.”
```

특징:

- 감독이 수용·조건부 수용·거부 가능
- 수용하면 공식 운영 목표로 등록
- 정당한 사유 없이 무시하면 감독 신뢰 하락
- 무리한 요청이면 감독이 반발
- 선수에게 알려질 경우 출전시간 약속으로 발전 가능

## 3단계: 경영진 지시

단장이 강한 권한을 행사합니다.

```text
“B는 이적 협상 중이므로 부상 위험을 피하기 위해 이번 주 출전시키지 마십시오.”
```

특징:

- 계약·의료·자산 보호 등 단장 업무와 관련된 상황에서 사용
- 감독이 따를 가능성이 높음
- 경기 전력 손실의 책임이 사용자에게 돌아옴
- 반복 사용 시 감독의 자율권 만족도 하락
- 유명 감독은 지시를 거부하거나 사임할 수 있음

경영진 지시로 포메이션이나 경기 중 교체까지 지정할 수는 없습니다.

- 풀백을 윙백으로 시험

사용자는 구체적인 전술 지시보다 일정 기간 포지션 실험을 요청합니다.

- 부상 복귀 선수 출전시간 제한
- 매각 협상 중인 선수 보호
- 중요한 경기 전 로테이션 검토

## 운영 목적 기용

- 유망주의 시장가치 상승
- 임대 전 경기 감각 확보
- 재계약 여부 판단
- 홈그로운 선수 육성
- 계약 옵션 발동 여부 관리

감독은 경기 성적을 이유로 반대할 수 있습니다.

# 9. 감독의 반응

감독은 요청을 무작위로 수락하거나 거부하지 않습니다.

판단 요소:

- 감독의 자율권 성향
- 단장과의 신뢰
- 요청의 전술적 타당성
- 선수 능력과 폼
- 부상·피로
- 경기 중요도
- 선수와 감독의 관계
- 이사회 정책
- 계약상 출전시간 약속
- 최근 성적
- 대체 선수의 존재

반응 유형:

```text
수용
조건부 수용
시험 기용 동의
추후 재검토
전술적 이유로 거부
의료적 이유로 거부
강하게 반발
이사회에 문제 제기
사임 경고
```

감독은 거부할 때 가능한 범위에서 이유를 설명해야 합니다.

# 10. 책임 귀속

사용자가 기용 압박을 행사했다면 결과에도 영향을 줘야 합니다.

예:

- 사용자가 출전을 강요한 유망주가 부진  
  → 감독 평가에는 일부 참작, 단장 판단에 대한 언론 비판

- 감독이 부상 위험을 경고했지만 사용자가 출전을 요구  
  → 재부상 시 단장·의료 정책 신뢰 하락

- 감독의 반대를 무릅쓰고 기용한 선수가 성공  
  → 단장의 선수 평가 신뢰 상승

- 감독이 공식 요청을 무시했지만 팀이 승리  
  → 성적은 긍정적이나 권한 갈등은 남음

결과만 보고 누가 항상 옳았다고 판정하지 않고, 당시 정보와 결정의 합리성을 함께 평가합니다.

- 감독과 단장의 갈등이 임계점에 도달

   하이재킹, 대체 선수 영입, 마감일 행동과 시장 가격 형성을 정합니다.

# 2-1. 스카우팅 시스템 설계안

## 기본 원칙

- 개별 스카우터 능력치 없음
- 선수 능력치는 관찰 단계에 따라 범위로 표시
- 관찰이 깊어질수록 범위가 좁아짐
- 낮은 확률로 실제 능력이 추정 범위 밖에 있을 수 있음
- 같은 선수를 다시 관찰할 때 평가가 무작위로 뒤집히지 않음
- 히든 능력은 완전 관찰 후에도 정확한 숫자를 공개하지 않음
- 선수 영입 후 기본 능력치의 실제 표시값이 공개됨
- 스카우팅은 정답이나 가성비 여부를 알려주지 않음

## 관찰 단계

### 0단계: 미관찰

공개 정보만 확인할 수 있습니다.

```text
이름
나이
국적
소속 구단
주 포지션
주발
신장
이번 시즌 공개 기록
대략적인 시장가치
계약기간 추정
```

능력치는 표시하지 않습니다.

### 1단계: 기본 조사

짧은 영상·데이터 조사와 공개 기록을 이용한 평가입니다.

- 소요 시간: 약 3~7일
- 능력치 범위 폭: 일반적으로 4~5
- 실제 능력이 범위 안에 있을 확률: 약 70%
- 역할과 특성은 일부만 확인
- 히든은 거의 알 수 없음

```text
TEC 13~17
ATT 11~15
DEF  8~12
PHY 14~18
TAC 10~14
MEN 11~15

예상 역할: 측면 공격수
평가 신뢰도: 낮음
```

### 2단계: 표준 관찰

복수 경기와 최근 기록을 확인합니다.

- 소요 시간: 약 2~3주
- 능력치 범위 폭: 일반적으로 2~3
- 실제 능력이 범위 안에 있을 확률: 약 85%
- 주 역할과 주요 특성 확인
- 꾸준함·부상 위험 등에 대한 초기 평가

```text
TEC 15~17
ATT 12~14
DEF  9~11
PHY 15~17
TAC 11~13
MEN 12~14

예상 역할
- 전통적 윙어: 15~17
- 인사이드 포워드: 13~15

히든 관찰
- 꾸준함: 판단 유보
- 큰 경기: 정보 부족
- 부상 위험: 보통으로 추정
- 프로의식: 양호하다는 평가

신뢰도: 보통
```

### 3단계: 정밀 관찰

여러 경기, 데이터, 배경조사를 결합한 최종 보고서입니다.

- 소요 시간: 약 4~6주
- 능력치 범위 폭: 일반적으로 1~2
- 실제 능력이 범위 안에 있을 확률: 약 95%
- 역할 적합도와 주요 특성 대부분 확인
- 히든 능력에 대한 서술형 평가 제공
- 메디컬 위험은 여전히 별도 검사 필요

```text

ATT 13~14
DEF 10
PHY 16~17
TAC 12
MEN 13~14

역할 평가
- 전통적 윙어: 16
- 인사이드 포워드: 14~15
- 와이드 플레이메이커: 13

특성
- 빠른 최고 속도
- 정교한 크로스
- 약한 발 사용 회피
- 수비 가담이 불안정함

히든 관찰
- 꾸준함: 비교적 안정적
- 큰 경기: 충분한 표본 없음
- 부상 위험: 과거 근육 부상에 주의
- 프로의식: 양호

평가 신뢰도: 매우 높음
```

정밀 관찰을 완료해도 실제 내부 수치 `16.4` 같은 값은 알 수 없습니다.

# 일관된 오판 방식

보고서를 요청할 때마다 새로운 오차를 무작위로 생성하면 안 됩니다.

선수를 처음 관찰할 때 해당 구단에 대한 **고정 평가 편향**을 한 번만 생성합니다.

```text
선수 실제 TEC: 14.6

기본 조사: 15~18
표준 관찰: 15~17
정밀 관찰: 15~16
영입 후 표시: 15
```

초기에는 다소 과대평가했지만 관찰이 깊어지면서 실제 능력에 가까워집니다. 같은 관찰 단계에서 보고서를 다시 요청한다고 평가가 갑자기 `12~14`로 뒤집히지 않습니다.

## 중대한 오판

정밀 관찰 후에도 낮은 확률로 오판이 남을 수 있습니다.

- 실제 능력이 예상보다 1 낮거나 높음
- 숨은 부상 위험을 발견하지 못함
- 기존 팀 전술 덕분에 능력이 과대평가됨
- 약한 리그에서의 활약을 EPL 수준으로 잘못 환산
- 제한된 출전 표본으로 꾸준함을 잘못 판단

중대한 오판은 완전한 무작위가 아니라 다음 상황에서 증가합니다.

- 출전시간이 적음
- 유망주
- 장기 부상 복귀 직후
- 잘 알려지지 않은 리그
- 포지션을 자주 변경
- 한 시즌만 갑자기 활약
- 계약 문제로 정상적으로 출전하지 못함

# 구단별 차이의 단순화

개별 스카우터 능력은 없애더라도 모든 구단의 정보력이 완전히 같으면 부자연스럽습니다. 따라서 스태프 개인이 아니라 **구단 스카우팅 범위**만 세 단계로 둘 수 있습니다.

```text
스카우팅 범위: 제한적
- 동시 정밀 관찰 인원 적음
- 해외 기본 조사 시간 증가

스카우팅 범위: 표준
- EPL 구단 기본 수준

스카우팅 범위: 광범위
- 동시 관찰 인원 증가
- 다양한 지역의 기본 정보 확보
```

이 차이는 능력치 평가 정확도가 아니라 다음에만 영향을 줍니다.

- 동시에 관찰할 수 있는 선수 수
- 보고서 작성 속도
- 자동으로 발견되는 선수 범위
- 알려지지 않은 리그의 선수 검색 가능성

따라서 부유한 구단이라고 선수 능력치를 더 정확하게 맞히는 것은 아니지만, 더 많은 선수를 더 빠르게 조사할 수 있습니다.

# 계약·가치 정보의 불확실성
